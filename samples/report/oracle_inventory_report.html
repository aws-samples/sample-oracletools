How to read the metrics

(click to expand)
Key data points for performance sizing
Minimum requirements per database row; no headroom is added. vCPU = min(max(DB CPU Avg P99, DB CPU Max P90), max(host CPU Avg P99, host CPU Max P90)), or 0.75 × host vCPUs when a DB CPU value is 0. Memory = SGA+PGA (RAC: SGA / nodes × (1 + 0.2 × (nodes − 1)) + PGA), or 0.9 × host memory when SGA+PGA is 0. Storage = max(0.8 × allocated, used). IOPS = max(DB IOPS Avg P99, DB IOPS Max P50). Throughput = max(DB throughput Avg P99, DB throughput Max P50). Storage type: gp3 when DB IOPS Max P50 < 64,000 and DB throughput Max P50 < 4,000 MB/s; io2 up to 256,000 IOPS and 16,000 MB/s. Every row is sized on its own, including CDB$ROOT; the CDB$ROOT row carries host-level CPU, so do not add it to its PDBs.
Collection mode
AWR: percentiles over AWR snapshots (default hourly) for up to the last 30 days (Diagnostics Pack licence required). STATSPACK: percentiles over STATSPACK snapshot intervals for up to the last 30 days; STATSPACK has no within-interval peaks, so its 'Maximum' columns are percentiles of interval averages. NOAWR: GV$SYSMETRIC_SUMMARY / GV$CON_SYSMETRIC_SUMMARY, i.e. the last ~60 minutes only.
CPU Avg P99 / CPU Max P90
Number of CPUs busy (vCPU-equivalents), not a percentage. Avg P99 is the 99th percentile of the per-snapshot averages; Max P90 is the 90th percentile of the per-snapshot peaks. Host rows use 'Host CPU Usage Per Sec' (all processes on the server); PDB rows use the PDB's own 'CPU Usage Per Sec'.
Peak CPU utilisation
max(CPU Avg P99, CPU Max P90) divided by the vCPU count of the server.
IOPS Avg P99 / IOPS Max P50
Total (read + write) I/O requests per second: 'Physical Read Total IO Requests Per Sec' + 'Physical Write Total IO Requests Per Sec' per snapshot. Avg P99 is the 99th percentile of the per-snapshot averages, Max P50 the median of the per-snapshot peaks (read peak + write peak, a slight over-estimate).
Throughput Avg P99 / Max P50
Total (read + write) MB/s from 'Physical Read/Write Total Bytes Per Sec', same percentiles as IOPS.
Redo Avg P99 / Max P50
Redo generated, MB/s. Useful to size change data capture (AWS DMS / GoldenGate).
SGA+PGA, SGA, PGA
99th percentile of SGA, PGA ('total PGA allocated') and their sum per snapshot (AWR, STATSPACK), or current allocation (NOAWR), in GB, summed across RAC instances. Each is its own percentile, so SGA + PGA can differ slightly from SGA+PGA.
Storage allocated / used
Datafiles of the container / segments of application schemas (Oracle-maintained schemas excluded), in GB. The CDB$ROOT row covers only the root container's files; each PDB has its own row. Host total storage covers every container of the CDB.
HA setup / BI components
HA setup lists RAC (cluster_database = TRUE), Data Guard (this database is a standby, has a valid standby archive destination, or a Data Guard configuration with other members) and Active Data Guard (feature currently used). BI components lists Oracle BI, SOA Suite, Data Integrator and other Fusion Middleware repository schemas created by RCU (e.g. DEV_BIPLATFORM, DEV_MDS). The columns are hidden when no database has any.
Tables w/o PK / w/o key
Tables without a primary key, and tables with neither a primary key nor a unique index on NOT NULL columns (no key AWS DMS can use to identify rows).
Objects
Counts exclude Oracle-maintained schemas. Procedures and functions are standalone objects only; members of packages are not counted. Jobs are enabled scheduler jobs of application schemas.
RAC
The cluster row and the database-level metrics are summed across instances per AWR snapshot (non-AWR: summed across instances), then the percentile is taken, so they represent the whole cluster.
Network Avg / Max
'Network Traffic Volume Per Sec': Oracle client and database link traffic, MB/s. Despite the column names, 'Average' is the 99th percentile of the per-snapshot averages and 'Maximum' the median of the per-snapshot peaks.
